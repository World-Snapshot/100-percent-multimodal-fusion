● 很好的问题！让我解释一下数据量和架构设计的差异：

  1. 数据量问题

  **不完全相同！**这是关键差异：

  WSG方法：

  - 数据文件：100个融合文件
  - 每个epoch：遍历100个样本
  - 每个样本：1个3通道图像（已融合）

  传统方法（Normal）：

  - 数据文件：300个文件（3×100）
  - 每个epoch：遍历100个样本
  - 每个样本：需要加载3个单独文件，组合成1个3通道图像

  结论：每个epoch处理的样本数相同（100个），但WSG的I/O效率更高（读1个文件 vs 读3个文件）。

  2. 七种架构设计

  让我详细解释每种架构的设计思路：

  # 1. WSG Fusion - 你的创新
  输入：3通道融合图像 → UNet → 输出：3通道
  特点：直接处理预融合数据，时空对应天然保持

  # 2. Early Fusion - 早期融合
  输入：3个通道 → [拼接] → UNet → 输出：3通道
  特点：在输入层就合并，之后统一处理

  # 3. Middle Fusion - 中期融合
  输入1 → Encoder1 ↘
  输入2 → Encoder2 → [特征融合] → Decoder → 输出
  输入3 → Encoder3 ↗
  特点：分别提取特征，在中间层融合

  # 4. Late Fusion - 晚期融合
  输入1 → 完整UNet1 → 输出1 ↘
  输入2 → 完整UNet2 → 输出2 → [拼接] → 输出
  输入3 → 完整UNet3 → 输出3 ↗
  特点：独立处理到最后才合并（参数量最大）

  # 5. Concat Fusion - 拼接策略
  输入：3通道 → 1×1卷积混合 → UNet → 输出
  特点：简单的通道混合后处理

  # 6. Attention Fusion - 注意力机制
  输入 → 通道注意力 → 空间注意力 → UNet → 输出
  特点：学习通道和空间的重要性权重

  # 7. Contrastive Fusion - 对比学习
  输入 → 分离 → 3个编码器 → 投影到共享空间 → 融合解码
  特点：类似CLIP，学习模态间的对应关系

  3. 参数量差异

  WSG/Early/Concat/Attention: ~50K参数（单路径）
  Middle: ~70K参数（3个编码器+融合）
  Late: ~150K参数（3个完整UNet）
  Contrastive: ~90K参数（3个编码器+投影头）

  4. 关键洞察

  WSG的优势不仅在于效率，还在于：
  1. 数据一致性：预融合保证了时空对应
  2. I/O效率：减少文件读取次数
  3. 参数效率：用最少的参数处理融合信息
  4. 训练稳定性：不需要学习如何对齐多个模态

  这就是为什么WSG理论上能达到300%效率的原因——用1/3的数据文件达到相同甚至更好的效果。

## 评估指标说明

### 四种效率评估方法
1. **时间效率** = Training Time / Parameters × 1000
   - 衡量每1K参数的训练时间成本

2. **收敛效率** = Epochs / Parameters × 1000  
   - 衡量每1K参数需要的训练轮数

3. **时间利用率** = Training Time / Epochs
   - 衡量每个epoch的平均时间

4. **综合效率** = (Time × Epochs) / Parameters × 1000
   - 综合考虑时间和收敛速度的效率指标（越低越好）
